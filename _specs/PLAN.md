## Как устроен узел

| Поле | Правило |
|---|---|
| **№** | Постоянный. `К-01` остаётся `К-01` навсегда — на него ссылаются ветка, PR, коммит и субагент. Номера не переиспользуются даже после `закрыто` |
| **Узел** | Одна строка. Что должно стать правдой |
| **Состояние** | Только из перечня ниже. Записанное рукой состояние — гипотеза, пока нет прибора |
| **Родитель** | Обязателен. `корень` пишет только слой `Я-NN`; линия стоит на слое, рабочий узел — на линии или узле. Сирот нет |
| **Подробность** | Путь к design-doc в `_specs/`, либо `—` |

**Перечень состояний** (закрытый):

`замысел` → `вердикт дан` → `в работе` → `влито` → `выкачено` → `закрыто`

плюс `ждёт вердикта` (нужен ответ Alex, кодом не решается) и `не делаем` — **всегда с причиной**.

**Ярусы.** Слой `Я-NN` — рубрика с родителем `корень` и состоянием `—`. Линия `Л-NN` стоит на слое. Рабочие узлы стоят на линии: `К-` конгресс, `С-` контент сайта, `О-` обвязка (выкатка, CI, гигиена, древо), `Т-` сценарное тестирование. Клеток `Э-NN` и фактов `F-NN` в этом древе нет: заведём, когда появится второй прибор, который их меряет.

**Связь с коммитом.** Коммит, двигающий узел, несёт трейлер отдельной строкой **над** блоком `Co-Authored-By`:

```
Plan-Item: К-01
```

`влито` = трейлер найден в истории `main`. `выкачено` = коммит достижим из метки выкатки (`refs/deploys/prod`, ставится узлом `О-03`). До появления метки «выкачено» пишется рукой по факту зелёного деплоя и проверки `/api/health` — это оговорено в узле.

**Ствол репозитория:** `main` (`origin/HEAD → origin/main`). Ветки `fix/*`, `feat/*`, `docs/*`, `chore/*`; мерж только через PR, финальные ворота — Alex.
