## 1. Что пожаловались и что на самом деле сломано

Три жалобы администратора. Каждая проверена руками на коде, на venv проекта и на публичном API прода. Отчёты трёх Opus-агентов (бэкенд, фронтенд, процесс) сверены; несущие утверждения воспроизведены самостоятельно.

### 1.1 «Секции не добавляются» — корень не в секциях, а в днях

**Подтверждено, воспроизведено.** В `backend/schemas/congress.py:187,198,211,354` поле называется `date` и объявлено как `date: Optional[date] = None`. Имя поля затеняет тип `date` из `datetime`, и Pydantic v2 резолвит аннотацию в `NoneType`:

```
CongressProgramDayCreate.model_fields['date'].annotation  ->  <class 'NoneType'>
date='2026-05-01'  -> 422 Input should be None
date=''            -> 422 Input should be None
date отсутствует   -> OK
```

Админка всегда шлёт `date` строкой (`EMPTY_DAY.date = ''`, `CongressAdmin.jsx:46`; форма `value={editModal.date || ''}`, `:970`). Значит **день программы нельзя создать из админки ни при каких вводимых данных** — с 2026-02-23 (коммит `795cf10`), когда программа появилась. Это подтверждается продом: 0 дней при 9 спикерах.

Цепочка до жалобы: нет дней → `DaySelector` не рендерится (`CongressAdmin.jsx:626`) → `needsDay === true` (`:657`) → кнопка «Добавить секцию» не существует (`:784`), вместо неё `EmptyState` «Нет дней программы». Пользователь видит «секции не добавляются».

Второй удар: если день с датой появится в БД в обход API, `CongressProgramDayResponse` не сериализуется → 500 на `GET /congress-program-days` и на `GET /congresses/{id}/detail`, то есть ляжет вся публичная страница конгресса.

### 1.2 Тот же класс ошибки: пустая строка вместо `null` в датах и времени

**Подтверждено, воспроизведено.** Формы шлют `''` для незаполненных полей, Pydantic пустую строку датой/временем не считает:

| Схема | Поле | Ввод `''` | Следствие |
|---|---|---|---|
| `CongressSpeakerCreate` (`:283-284`) | `time_start`, `time_end` | 422 time_parsing | спикер без времени не создаётся |
| `CongressCreate` (`:17-18`) | `date_start`, `date_end` | 422 datetime_parsing | конгресс без дат не создаётся |

На проде все 9 спикеров с временем, конгресс с датами — админ обошёл это, заполняя всё. Но это та же ловушка, что и с днями, и она вылезет при первом «сохраню черновик потом».

### 1.3 Сопутствующие дефекты на пути «секция → доклад»

- `loadCongressData` собирает спонсоров/дни/спикеров через `Promise.all` (`CongressAdmin.jsx:472-482`): падение одного запроса обнуляет `programDays` → та же пустая вкладка «Секции», даже когда дни в БД есть.
- Форма спикера видит секции только выбранного дня (`sections` грузятся по `selectedDayId`, `:491-499`), а `DaySelector` на вкладке «Спикеры» скрыт (`:626`). Привязать доклад к секции второго дня из UI невозможно.
- Секцию нельзя перенести в другой день: `day_id` вырезается при update (`:528`), `CongressProgramSectionUpdate` его не принимает.
- `AdminFormField` не пробрасывает `required` в `<input>` (`AdminFormField.jsx:19` vs `:59-68`): секцию можно сохранить без названия, на публичной странице она превращается в пустую кнопку (`Congress.jsx:471`).
- Бэкенд не проверяет существование `day_id`/`congress_id` при create (`congress.py:206,270,340`): несуществующий родитель даёт 500 вместо 404.
- Загрузочные `catch` в админке глухие (`CongressAdmin.jsx:462,486,496,586`): объект ошибки не связан, статус и `detail` не видны ни пользователю, ни в консоли.

### 1.4 «Фото маленькие, текст большой»

**Подтверждено по коду.** Публичная страница, оба места рендера спикеров:

| Место | Фото | Текст |
|---|---|---|
| Вкладка «Программа» (`Congress.jsx:489`) | `w-14 h-14` = 56 px, `object-cover` | ФИО 16 px + 3 строки `text-sm`/`text-xs` |
| Вкладка «Спикеры» (`Congress.jsx:530`) | `w-16 h-16` = 64 px | то же |

Портретное фото в квадрате 56 px рядом с блоком текста высотой 80–100 px. У правления (`BoardMembers.jsx:148-160`, правилось в PR #3, #4) фото резиновое с `aspect-[3/4]` и долевой шириной колонки — образец есть в соседнем файле.

Бэкенд ни при чём: `/api/content/upload` (`content.py:38-53`) пишет байты как есть, без ресайза, лимита, проверки типа и конвертации HEIC. Pillow в `requirements.txt` нет. Значит фото на проде — оригиналы с телефона, ужатые CSS до 56 px. Это же означает: когда фото станут большими, страница начнёт тянуть мегабайты.

### 1.5 «Страница программы, открытая, разная по языку»

**Подтверждено.** Сейчас программа — шестая вкладка на `/congress/:id` (`Congress.jsx:120-127`), вкладка по умолчанию `'main'` (`:17`), состояние вкладки не в URL, отдельного маршрута нет (`App.jsx:96-97`). На телефоне полоса вкладок скроллится без видимого скроллбара (`:635`), вкладка «Программа» уезжает за край. Внутри — трёхуровневая навигация кнопками: виден ровно один день и одна секция. Сводного вида «вся программа» нет, прямой ссылки нет.

Данные для языков уже есть: у дней и секций `title_uz/en`, `description_uz/en` (`models.py:210-215, 228-233`), резолвер `L()` с фолбэком на RU (`Congress.jsx:78`) работает. Плюс мёртвый слой: колонки `program_ru/uz/en` у конгресса (`models.py:106-108`) — **ни формы в админке, ни рендера на странице**. И `info_letter_file_ru/uz/en` для файлов по языкам — форма есть, но семантика «информписьмо», не «программа».

Чего в модели нет: `is_active` у дней/секций (черновик сразу публичен), времени/зала у секции, отдельной сущности «доклад» (доклад = поля спикера, один спикер = один доклад).

## 2. Почему это дожило до пользователей: карта процесса

### 2.1 Как есть

```
разработчик ──commit──▶ ветка ──PR──▶ main ──push──▶ deploy.yml
                                  ▲                      │
                            ревью глазами          npm ci && build   (тесты: НЕТ, lint: НЕТ)
                            (единственный gate)          │
                                                   ssh: git checkout main
                                                   compose up --build backend
                                                   alembic upgrade head   (бэкап БД: НЕТ)
                                                   scp dist/
                                                   compose up -d          (health-check: НЕТ)
                                                          │
                                                       ПРОД  ◀── единственное окружение, staging НЕТ
                                                          │
                                                   пользователь = тестировщик
```

Факты, каждый проверен:

| Прибор | Есть? | Где |
|---|---|---|
| Триггер `pull_request` в CI | нет | `.github/workflows/deploy.yml:3-5` — только `push: main` |
| `npm test` в CI | нет; 100 тестов, 12 файлов, все зелёные за 15 с | `deploy.yml:22-26` |
| `npm run lint` в CI | нет; сейчас **exit 1: 20 ошибок, 26 предупреждений** | `frontend/eslint.config.js` |
| Бэкенд-тесты | нет вообще: ни pytest, ни conftest, ни тестовой БД | `backend/requirements.txt` |
| Тесты на страницы | 0 из 31 страницы, 0 из 6 роутеров | покрыты 10 UI-примитивов + `getField` |
| Health-check после деплоя | нет; `/health` есть в `main.py:58`, но nginx его не проксирует | `nginx/nginx.conf` |
| `healthcheck:` в compose | нет ни у одного сервиса | `docker-compose.prod.yml` |
| Версия изнутри продукта | нет: `version="1.0.0"` — константа с января | `main.py:29,54` |
| Откат | нет; `docker image prune -af` перед деплоем уничтожает предыдущий образ | `deploy.yml:44` |
| Seed для конгресса | нет: `seed_data.py` не создаёт ни одной congress-сущности | воспроизвести баг = 3 ручных шага |
| Design-doc до кода | применялся 1 раз (SSL), к конгрессу — никогда | `_specs/` |

Археология: весь тестовый набор появился одним коммитом `6f5ecdc` 2026-02-24 как часть «редизайна админки» и с тех пор не пополнялся. Семь правок конгресса после этого, включая три багфикса — ноль тестов. `backend/api/congress.py` не менялся с 2026-02-23. Это не «нет тестирования», а хуже: **инвентарь тестирования, изображающий процесс, при отсутствии процесса**. Правило без прибора.

Гигиена: `backend/venv/` в индексе (4128 файлов вопреки `.gitignore`), `backend/rheumatology.db` в индексе, `origin/master` жив после переименования, три влитых ветки не удалены, `.claude/settings.local.json` с путями старого расположения проекта.

### 2.2 Как должно быть

```
ветка ──PR──▶ ci.yml (pull_request):           ──merge──▶ main ──▶ deploy.yml:
              frontend: lint + test + build                        build с GIT_SHA
              backend:  pytest (sqlite)                            pg_dump перед alembic
              i18n: полнота ключей                                 compose up -d
              (красный CI = PR не мержится)                        smoke: GET /api/health
                                                                   sha в ответе == GITHUB_SHA
                                                                   иначе job красный
```

Мерило рабочего процесса — три прибора, которые краснеют сами:

1. **PR не мержится с красным CI** (branch protection на `main`, required check `ci`).
2. **Деплой красный, если прод не отвечает тем sha, который выкатывали.** Это и есть прибор для правила «смержено ≠ выкачено».
3. **Каждый багфикс приходит с тестом, который падал до фикса.** Прибор — ревью PR: диф без тестового файла на путь бага не принимается.

## 3. Варианты и выбор

### 3.1 Как чинить пустые строки в датах

| | A. Валидатор на бэкенде (`'' → None`, `mode='before'`) | B. Фронт шлёт `null` | C. Оба |
|---|---|---|---|
| Защищает от любого клиента | да | нет | да |
| Трогает файлов | 1 (schemas) | 1 (CongressAdmin) | 2 |
| Скрывает баг клиента | да, но это норма API | — | — |

**Выбран A.** Одно место, покрывается одним тестом, чинит сразу конгресс/день/спикера. Фронт не трогаем — меньше диф.

### 3.2 Что такое «страница программы»

| | A. Структурная (дни→секции→доклады) на отдельном маршруте | B. Свободный текст/PDF по языкам (`program_*`, файл) | C. A + B: структурная основная, текст/файл как дополнение |
|---|---|---|---|
| Работает без ввода дней/секций | нет | да | да |
| Разная по языку | автоматически, если UZ/EN заполнены (сейчас 0 из 9) | админ пишет три версии | обе |
| Прямая ссылка `/congress/:id/program` | да | да | да |
| Объём работы | средний | малый (колонки уже есть) | средний+ |

**Рекомендую C с оговоркой:** структурная программа — основной вид, весь конгресс на одной странице (дни аккордеоном, все раскрыты); блок «Полная программа (файл)» по языкам под ней, если файл загружен. Но если у ассоциации программа уже свёрстана в PDF и до 25.09 никто не будет вбивать 9+ докладов по дням, то **B закрывает жалобу быстрее**. Это решение Alex, см. §7.

### 3.3 Фото спикеров

Повторить паттерн правления: контейнер с `aspect-[3/4]`, долевая ширина, `object-cover`; текст под фото, а не сбоку. Ресайз на бэкенде (Pillow, max 1600 px, quality 85, HEIC→JPEG через `pillow-heif`) — отдельный узел P2, потому что жалоба закрывается CSS, а ресайз меняет зависимости образа.

## 4. План: узлы, порядок, приборы

Каждый узел — одна ветка, один PR, один Opus-субагент, разведение **по файлам**. Ни один узел не начинается без approve этого документа. Порядок диктует срок 2026-09-25.

### P0 — программа конгресса работает (до 2026-09-18)

**P0.1 Бэкенд: схемы + тесты** — файлы `backend/schemas/congress.py`, `backend/api/congress.py`, `backend/requirements-dev.txt`, `backend/tests/**`, `backend/pytest.ini`.

## 5. Порядок исполнения и параллельность

```
P0.1 (backend) ──▶ P0.2 (admin)          ┐
```

Правила для субагентов (Opus, только они):
- Каждый узел — свой worktree, своя ветка `fix/*` или `feat/*`, git-операции только через `git -C <worktree>`.
- TDD: тест, который падает, до правки. Вывод падения и прохода — в описание PR.
- Отчёт агента — гипотеза: перед PR несущие утверждения (тест падал, тест прошёл, lint зелёный) проверяются главной сессией своими руками.
- PR открывает агент; мержит только Alex.
- Мерж → строка в `_specs/README.md`: узел → PR → состояние.
