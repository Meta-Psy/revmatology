# Design: выдача именных сертификатов участникам конгресса

**Узел:** `К-11` · **Родитель:** `Л-01` (конгресс) · **Реестр:** `_specs/PLAN.md` · **Процесс:** `P-07` в `_specs/processes.yaml` · **Дата:** 2026-09-22 · **Одобрено:** Alex, 2026-09-22 («подход А устраивает», «записывай design-doc и сразу приступай к реализации. Дальше сам»)
**Источник требований:** ТЗ организаторов (Sardor, 2026-09-22) — «Модуль автоматической выдачи сертификатов участникам конгресса», §1–18.
**Срок:** не горит (решение Alex 2026-09-22). Прод-инфраструктуру (nginx, compose) до 2026-09-27 не трогаем — решение Alex 2026-09-15 по `О-09`.

## 1. Задача

Организаторы дают пустой PDF-сертификат (место под Ф.И.О. пустое) и список участников. Участник на сайте находит себя по Ф.И.О. (с подсказками из списка), при наличии телефона в списке подтверждает его и получает PDF, где его **официальное** Ф.И.О. из списка вписано каллиграфическим шрифтом по центру отведённой рамки. Не больше 5 выдач на участника. Человек вне списка сертификат получить не может.

Хранить 300 готовых PDF не нужно: на сервере лежит один шаблон и один шрифт, каждый сертификат собирается в памяти за доли секунды наложением слоя с именем на исходную страницу; на диск ничего не пишется.

## 2. Решения brainstorming (2026-09-22)

| Вопрос | Решение |
|---|---|
| Источник списка | Отдельный список получателей, **не** `congress_registrations`. Организаторы шлют в любом формате, Claude приводит к CSV; дальше CSV грузится через админку |
| Обновление списка | Раздел в админке: импорт CSV, правка/добавление/удаление строк, сброс счётчика |
| Сборка PDF | Подход А: reportlab рисует прозрачный слой с именем, pypdf накладывает его на страницу шаблона. Отвергнуты: PyMuPDF (AGPL), сборка в браузере (шаблон и шрифт публичны → сертификат на любое имя) |
| Ограничение частоты | В приложении, не в nginx (см. «Срок») |

## 3. Данные — миграция `005`

**`certificate_templates`** — одна строка на конгресс (`congress_id` UNIQUE, FK `congresses.id` ON DELETE CASCADE):

| Поле | Тип | Смысл |
|---|---|---|
| `pdf` | LargeBinary, nullable | Байты шаблона. **В БД, а не в `/uploads`**: nginx отдаёт `/uploads` публично целиком, пустой бланк утёк бы |
| `pdf_filename` | String(255) | Имя загруженного файла — для админки |
| `box_x_mm`, `box_y_mm`, `box_w_mm`, `box_h_mm` | Float, по умолчанию 58 / 94 / 181 / 15 | Рамка имени в мм **от левого верхнего угла** первой страницы (так её меряют глазами в просмотрщике) |
| `font_max_pt`, `font_min_pt` | Float, по умолчанию 40 / 16 | Диапазон кегля |
| `text_color` | String(7), по умолчанию `#1B3A7A` | Цвет имени и номера (синий дизайна бланка) |
| `number_box_x_mm`, `number_box_y_mm`, `number_box_w_mm`, `number_box_h_mm` | Float, **nullable**, по умолчанию 259 / 183 / 22 / 7 | Рамка порядкового номера, те же мм от верхнего левого угла. Все четыре NULL — номер не печатается; частично заполненная рамка не сохраняется (422) |
| `number_font_pt` | Float, по умолчанию 14 | Кегль номера (постоянный, без подбора) |
| `next_number` | Integer, NOT NULL, по умолчанию 1 | Счётчик порядковых номеров конгресса: номер, который получит следующая вставка |
| `is_open` | Boolean, по умолчанию false | «Выдача открыта» |
| `updated_at` | DateTime | — |

**`certificate_recipients`**:

| Поле | Тип | Смысл |
|---|---|---|
| `congress_id` | FK, index | — |
| `full_name` | String(300) | Ровно как в списке — идёт на сертификат |
| `name_key` | String(300), index | `normalize_name(full_name)` — для поиска |
| `phone_digits` | String(20), nullable | Только цифры |
| `download_count` | Integer, default 0 | Технический счётчик выдач (ТЗ §14) |
| `number` | Integer, NOT NULL, `UNIQUE (congress_id, number)` | Порядковый номер сертификата в конгрессе (поле «No. ____» бланка) |
| `created_at` | DateTime | — |

**Порядковый номер** (решение Alex 2026-09-22). Назначается при вставке — импорт (в порядке строк файла) и ручное добавление — из счётчика `certificate_templates.next_number` конгресса (строка шаблона создаётся лениво, как для настроек): строка блокируется `SELECT … FOR UPDATE`, счётчик увеличивается в той же транзакции, что и вставка. **Номер не выдаётся повторно в пределах конгресса**: удалённый получатель мог уже скачать сертификат со своим номером, поэтому удаление счётчик не трогает (дырка остаётся, и после удаления *последнего* номера следующий добавленный получит следующий, а не тот же). Постоянный: правка и сброс счётчика скачиваний его не меняют. `replace` сбрасывает счётчик в 1, **только если ни у одного текущего получателя конгресса нет `download_count > 0`**; иначе нумерация продолжается (ответ импорта: `numbering_restarted`). Известный предел: админский «сбросить счётчик» обнуляет `download_count`, и после него скачивание этого получателя для правила `replace` уже не видно. Уникальный индекс `(congress_id, number)` → **409** `number_conflict` оставлен страховкой (в том числе на гонку ленивого создания строки шаблона).

**Значения по умолчанию** подогнаны под настоящий бланк организаторов (A4 альбомный 842.65×596.35 pt, весь растровый) по пробному PDF: имя — над длинной линией под «of participation», номер — на линии после «No.» справа внизу.

Миграция `005` дописана на месте (номер, рамка номера, счётчик `next_number`): на 2026-09-22 она нигде не применена.

Шаблон отдельной таблицей, а не колонками `Congress`: иначе каждый список конгрессов тянул бы мегабайты PDF.

## 4. Чистые функции (без БД, покрываются unit-тестами)

`backend/functions/certificate_names.py`:
- `normalize_name(s)` — сначала `unicodedata.normalize("NFC")` (разложенные «й»/«ё» = составные), затем `casefold`, обрезка, схлопывание пробелов, `ё→е`, все апострофы (`ʻ ʼ ' ’ ‘ \` ´`) → `'`. ТЗ §4.
- `phone_digits(s)` — только цифры.
- `clean_phone(s)` — телефон для хранения: пусто → нет телефона; меньше 9 цифр (`short`) или больше 15 (`invalid`, E.164 — обычно два номера в ячейке) → тоже нет телефона, с причиной. Короткий номер в базе запер бы участника навсегда: сравнение идёт по 9 последним цифрам.
- `phones_match(stored, entered)` — сравнение последних 9 цифр (`+998 90 123 45 67` = `998901234567` = `90 123 45 67`); введено < 9 цифр → не совпало. Короче 9 в базе не хранится. ТЗ §7.
- `certificate_filename(full_name)` — `Certificate_<латиница>.pdf`: транслитерация RU + узбекской кириллицы (ш→sh, ч→ch, ў→o, ғ→g, қ→q, ҳ→h, ё→yo, ю→yu, я→ya, …), апострофы убираются, пробелы → `_`, остаётся `[A-Za-z0-9_-]`. Заголовок отдаёт ещё `filename*=UTF-8''<оригинал>`. ТЗ §13.
- `parse_recipients_csv(bytes)` — кодировка `utf-8-sig`, запасная `cp1251`; разделитель `csv.Sniffer` из `, ; \t`; колонка имени по заголовку (`ФИО`, `Ф.И.О.`, `full_name`, `name`, `F.I.Sh.`, регистр/пробелы не важны) **или** тройка `Фамилия`/`Имя`/`Отчество` (`last_name`/`first_name`/`patronymic`), склеиваемая через пробел; телефон — `Телефон`/`phone`/`tel`, необязателен. Телефон проходит `clean_phone` (счётчики `short_phones`, `invalid_phones` — строка остаётся, без телефона); Ф.И.О. длиннее 300 знаков (колонка `String(300)`) — строка отбрасывается, счётчик `too_long_names`. Возвращает строки + отчёт: принято, пустых, дублей внутри файла (по `name_key` + `phone_digits`, после чистки телефона). Нет колонки имени → ошибка с перечнем найденных заголовков.

`backend/functions/certificate_pdf.py`:
- `format_number(n)` — номер на сертификате с ведущими нулями до трёх знаков: `001`, `007`, `123`, `1234`.
- `render_certificate(template_pdf, name, box, font_max, font_min, color, outline=False, number=None, number_box=None, number_font_pt=14) -> bytes`. Берётся первая страница шаблона (остальные страницы, если есть, копируются без изменений). Рамка переводится из мм-от-верха в пункты-от-низа с учётом `mediabox` (и `/Rotate`, если задан). Кегль: от `font_max` вниз шагом 0.5 pt, пока `stringWidth ≤ box_w` и высота строки ≤ `box_h`. Не влезает на `font_min` → две строки, разрыв по пробелу, ближайшему к середине, кегль подбирается так же для обеих строк. Центр по горизонтали; по вертикали — по середине между ascent и descent шрифта. Номер (`number`, уже отформатированный) рисуется, только если заданы и он, и `number_box`: по центру своей рамки, тем же шрифтом и цветом, кеглем `number_font_pt`, по вертикали — так же, как имя. `outline=True` рисует тонкие контуры обеих рамок — только для «пробного PDF». Шрифт встраивается (подмножество), исходная страница не растеризуется.
- Шрифт — `backend/assets/fonts/Caveat-Medium.ttf` + `OFL.txt` + `README.md` (происхождение и команда пересборки). Выбор — §8.

## 5. API — новый модуль `backend/api/certificates.py`, подключён в `api/__init__.py` под `/api/congress`

**Публичные:**

| Метод | Путь | Поведение |
|---|---|---|
| GET | `/congresses/{id}/certificates/status` | `{"open": bool}` — выдача открыта и шаблон загружен |
| GET | `/congresses/{id}/certificates/suggest?q=` | `q` не длиннее 200 знаков, иначе 422. Закрыто → `[]`. Меньше 3 непробельных символов → `[]`. Каждое слово запроса — подстрока `name_key` (порядок слов любой). Не больше **7** результатов, сортировка по `full_name`. Ответ: `[{id, full_name, needs_phone}]` — **без телефонов** (ТЗ §15) |
| POST | `/congresses/{id}/certificates/issue` `{recipient_id, full_name, phone?}` | `full_name` — имя из выбранной подсказки (≤ 300 знаков): `normalize_name(full_name)` должен совпасть с `name_key` получателя, иначе перебором `recipient_id` можно было бы забрать чужой PDF. Закрыто / нет получателя в этом конгрессе / телефон не совпал / имя не совпало → **404** `not_found` (одинаково — не подсказываем, что именно не так), всё до списания. Лимит → **403** `limit_reached`. Иначе условное списание `UPDATE … SET download_count = download_count + 1 WHERE id = :id AND download_count < 5 RETURNING` (атомарно при 2 воркерах uvicorn); байты шаблона читаются только после списания (до него — настройки без колонки `pdf`), сборка PDF с номером получателя (`format_number(number)`, если рамка номера задана), ответ `application/pdf` с `Content-Disposition: attachment`. Сбой сборки → счётчик возвращается, 500 |

Ограничение частоты: скользящее окно в памяти процесса по IP (`X-Real-IP` от nginx, запасной — `request.client.host`): `suggest` 60/мин, `issue` 20/мин (на площадке конгресса и у мобильных операторов с CGNAT за одним IP много людей), превышение → **429** `too_many_requests`. При двух воркерах фактический порог до ×2 — принимаем. Опустевшие окна удаляются (раз в окно — проход по всем ключам), IP не копятся. Честно о пределе: 3 символа + 7 результатов + частота сильно затрудняют выгрузку всего списка, но не делают её невозможной; для ~300 участников и ТЗ §15 («затруднить») достаточно. Известный остаток: у участника без телефона любой, кто знает его Ф.И.О. (найдёт в подсказках), может израсходовать его 5 выдач — следствие ТЗ §7 («нет телефона — проверка только по Ф.И.О.»); смягчает частота, лечится сбросом счётчика в админке.

**Админские** (`Depends(get_current_admin)`):

| Метод | Путь | Поведение |
|---|---|---|
| GET / PUT | `/congresses/{id}/certificate-settings` | Настройки без байтов PDF (+ `has_template`, `pdf_filename`), включая `number_box_*` и `number_font_pt`; PUT частичный. `null` у рамки номера — «не печатать» (все четыре сразу, иначе 422 `number_box_incomplete`), у остальных полей — «не менять» |
| POST | `/congresses/{id}/certificate-template` | multipart, только PDF (проверка `%PDF-` и что pypdf открывает), лимит 20 МБ |
| POST | `/congresses/{id}/certificate-preview` `{name}` | PDF с номером `000` и контурами обеих рамок; счётчиков не трогает |
| GET | `/congresses/{id}/certificate-recipients?q=&skip=&limit=` | `{items, total}`, у каждого `number`; сортировка по `number`; телефоны видны (админ) |
| POST | `/congresses/{id}/certificate-recipients` | Добавить одного, номер — из счётчика `next_number` (не повторяется). Ф.И.О. > 300 знаков → 422; телефон 1–8 или > 15 цифр → 422 `invalid_phone` (пустой — «без телефона»); номер занят параллельной вставкой → 409 `number_conflict` |
| PUT / DELETE | `/certificate-recipients/{rid}` | Правка (пересчёт `name_key`, `phone_digits`; проверки те же, что при добавлении) / удаление |
| POST | `/certificate-recipients/{rid}/reset` | `download_count = 0` |
| POST | `/congresses/{id}/certificate-recipients/import` | multipart `file`, `mode=append|replace`, `dry_run=true|false`. Ответ: `{accepted, empty_rows, duplicates_in_file, skipped_existing, short_phones, invalid_phones, too_long_names, will_insert, inserted, sample, columns, numbering_restarted, first_number}` — отчёт `parse_recipients_csv` + `skipped_existing` (для append — уже есть такой `name_key`+`phone_digits`) + `will_insert` (сколько вставится: append — `accepted − skipped_existing`, replace — `accepted`; без `dry_run` равно `inserted`). `dry_run` считает ровно так же, как настоящий импорт. `replace` удаляет всех получателей конгресса вместе со счётчиками; `replace` с `accepted = 0` (не `dry_run`) → 400 `empty_replace`, ничего не удаляется. Номера — по порядку строк файла из счётчика конгресса; `replace` начинает с 1, только если никто ещё не скачивал (`numbering_restarted=true`), иначе продолжает. `first_number` — номер первой вставленной строки; `dry_run` возвращает оба поля так же, админка при `replace` и `numbering_restarted=false` показывает «Нумерация продолжится с N (сертификаты уже скачивали)»; конфликт номера → 409 `number_conflict` |

## 6. Фронтенд

- `services/api.js`: методы в `contentAPI`/`adminAPI` по образцу файла. `issue` — `responseType: 'blob'`; ошибка приходит блобом → разобрать JSON и взять `detail`.
- **Страница** `pages/CongressCertificate.jsx`, маршрут `/congress/:id/certificate` (ленивым куском по образцу `К-10`). Заголовок «Получить сертификат участника», инструкция «Введите Ф.И.О., указанные при регистрации на конгресс». Поле Ф.И.О. с подсказками (задержка 300 мс, от 3 символов, клавиатура ↑↓ Enter Esc, `role="combobox"`/`listbox`). Свой текст ввести нельзя: кнопка «Найти сертификат» активна только при выбранном участнике; правка текста снимает выбор. `needs_phone` → поле «Номер телефона» (`inputmode="tel"`). Ответы: 404 → «Участник с указанными данными не найден. Пожалуйста, проверьте правильность введённых данных.»; 403 → «Достигнуто максимальное количество скачиваний сертификата.»; 429 → «Слишком много попыток, подождите минуту». Успех → кнопка «Скачать сертификат» (скачивание блоба из памяти через `<a download>`, без повторного запроса). Выдача закрыта → сообщение «Выдача сертификатов пока не открыта».
- **Ссылка** «Получить сертификат» на странице конгресса рядом с программой — только при `status.open`.
- **i18n:** ключи `certificate.*` во всех трёх `locales/{ru,uz,en}.json` (гейт `i18n.test.js`). Тексты ТЗ — RU дословно.
- **Админка:** вкладка «Сертификаты» в `CongressAdmin.jsx`, сам код — отдельным файлом (`CongressAdmin.jsx` уже 1370 строк). Три блока на примитивах `components/admin/*`: (1) настройки — загрузка шаблона, рамка имени в мм, кегль, цвет, рамка номера («пусто: номер не печатается») и кегль номера, «Выдача открыта», поле «Имя для пробы» + «Пробный PDF» (открывается в новой вкладке); (2) импорт CSV — файл, режим «добавить / заменить всех» (замена — через `ConfirmDialog` со словами «счётчики скачиваний обнулятся»), сначала `dry_run` со сводкой, затем «Загрузить»; (3) `AdminTable` получателей: поиск, «№» (с ведущими нулями, как на PDF), Ф.И.О., телефон, выдано N из 5, действия «изменить / сбросить счётчик / удалить», «Добавить».

## 7. Проверка

- **pytest, чистые функции:** нормализация (пример ТЗ §4), телефоны (три формы ТЗ §7 + короткий ввод), имя файла (RU, узб. кириллица, узб. латиница с `ʻ`), CSV (`;`/`,`, cp1251, BOM, ФИО одной колонкой и тройкой, без телефона, пустые строки, дубли, нет колонки имени).
- **pytest, PDF:** страниц столько же, сколько в шаблоне; `extract_text` итога содержит имя; шрифт встроен; короткое имя крупнее длинного; самое длинное имя ТЗ §11 укладывается в ширину рамки; сверхдлинное — две строки. Шаблон для тестов генерируется reportlab в фикстуре.
- **pytest, шрифт (прибор):** cmap выбранного TTF покрывает весь набор знаков §8 — сломается, если кто-то подменит шрифт.
- **pytest, API:** подсказки без телефонов, ≤ 7, < 3 символов → пусто, закрыто → пусто; выдача: телефон трёх форм, чужой телефон → 404, чужой конгресс → 404, шестая выдача → 403, сбой сборки возвращает счётчик; 429 по частоте; админские маршруты без токена → 401/403; импорт append/replace/dry_run.

## 8. Шрифт

Обязательное покрытие: `А–Я а–я Ё ё`, `Ў ў Қ қ Ғ ғ Ҳ ҳ`, `A–Z a–z`, `ʻ` (U+02BB), цифры (номер), пробел, дефис, точка. Контуры TrueType (`glyf`), статический экземпляр — reportlab не встраивает CFF. Лицензия OFL/Apache.

**Выбран Caveat** (решение Alex 2026-09-22, под настоящий бланк): статический экземпляр wght=500 из вариативного `Caveat[wght].ttf` Google Fonts (`fonttools varLib.instancer "Caveat[wght].ttf" wght=500 --static`), файл `Caveat-Medium.ttf`, OFL 1.1. Прежний кандидат Cormorant Infant удалён.

В Caveat **нет U+02BB**. Перед отрисовкой он (и другие апострофы, которых нет в шрифте) заменяется на первый имеющийся запасной знак: `‘` (U+2018) — для узбекского oʻ/gʻ он ближе всего, затем `’`, затем `'`. Подмена — часть `render_certificate`; тест проверяет, что в PDF для «Oʻrinboyeva» стоит `‘`. Прибор покрытия: вся кириллица + `ЎўҚқҒғҲҳ` + латиница + цифры есть; для `ʻ` — есть хотя бы один запасной знак; лицензия и README лежат рядом и относятся к этому файлу.
