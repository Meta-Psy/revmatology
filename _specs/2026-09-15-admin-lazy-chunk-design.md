# К-09 · Публичные страницы не качают код админки

**Родитель:** `К-09` → `Л-01` · **Реестр возврата:** `_specs/PLAN.md` · **Ветка:** `feat/admin-lazy-chunk` · **Поручение:** Alex 2026-09-15, до заморозки 2026-09-21

## Цель

Публичный вход (`index-*.js`) весил 872 кБ / 213 кБ gzip, потому что `App.jsx` статически тянул `AdminLayout`, 15 страниц `pages/admin/*` и кит `components/admin/*`. Посетитель сайта качал админку, которой не пользуется. Вход должен её не содержать, и это должно проверяться при каждой сборке.

## Решения

1. **Один ленивый кусок `pages/admin/AdminApp.jsx`, а не 15.** Админ качает его один раз (≈29 кБ gzip) и дальше ходит по меню без догрузок. На медленном канале это лучше, чем ждать на каждом переходе.
2. **`AdminChunkBoundary` вокруг `Suspense`.** Обрыв на медленном канале отклоняет `import()`, и без boundary получается белый экран. Boundary ловит и любую ошибку рендера внутри админки, поэтому текст нейтральный: «Раздел админки не открылся», подпись «Обновите страницу. Если не помогло — сообщите разработчику.» и кнопка «Обновить страницу».
3. **Сторож сборки `vite-plugins/adminChunkGuard.js`.** Правило без прибора не живёт. `vite build` падает, если во вход попал модуль из `src/pages/admin/` или `src/components/admin/` либо gzip входа больше `ENTRY_GZIP_BUDGET` (192 КиБ = замер + ~10 КиБ). Бюджет поднимают осознанно, правкой константы. CI уже запускает `npm run build`.

Оценка учитывает только байты JS и CSS: без задержки, TLS, картинок, шрифтов и API. Измеренные 10–13 с складываются и из них.

**Вывод:** админка занимала только ~13 % gzip входа. Больше всего во входе весят `react-dom` (540 КиБ до минификации) и публичные страницы (`src/pages`, 452 КиБ, из них `Home` 84, `Congress` 75, `Activities` 47, `Schools` 42, `Rheumatology` 38). Следующий шаг для заметного выигрыша — ленивые публичные страницы.
